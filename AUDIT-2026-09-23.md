## 🔴 Críticos (bloquean deploy)

- **[web][npm-audit]** `next@16.3.0` cae dentro del rango vulnerable (16.0.0–16.3.2) de **RCE no autenticado en servidores hosteados en Windows** (incluye variante vía Image Optimization API con AVIF). `package.json:24`, resuelto en `node_modules/next` v16.3.0 → parche en ≥16.3.3.
  - **Impacto:** el proyecto corre en Windows 11 (`cgodoys`) — este es exactamente el entorno afectado, explotable sin autenticación previa.
  - **Fix:** `npm audit fix` (o pin manual a `"next": "^16.3.3"` si `fix` no alcanza la versión parcheada — verificar changelog de Next.js). Correr `npx vitest run` + `npm run build` después para confirmar que no rompe nada.

## 🟠 Alta prioridad

- **[cache][N+1]** `src/features/cash-flow/services/refresh.ts` — `refreshCashFlowReport` (líneas 544-1131) hace ~15-20 queries `await supabase...` secuenciales por CADA mes del rango dentro de `for (const mes of meses)` (línea 691), más un loop interno de `pctSobreRemuneracionAprendido` que awaitea `montoCashFlowPorPeriodoStr` fila por fila (línea 505-515). Con 12 meses, esto son cientos de round-trips secuenciales — la UI ya advierte "puede tomar 1-2 min" (`refresh-report-button.tsx:45`) y hay mediciones previas de 9+ minutos.
  - **Fix:** precargar las 4 tablas chicas involucradas fuera del loop de meses (mismo patrón ya probado en `dotacion-total.ts:510-611`) — baja de ~1.170 queries a ~6.
- **[cache][arquitectura]** 0% de cobertura de cache de datos: `rg -c 'useSWR|@tanstack/react-query' src/` → 0; `rg -n "export const revalidate" src/app` → 0; `Cache-Control/s-maxage` → 0; y las 3 páginas core (`reporte`, `fuentes`, `dotacion`) están en `export const dynamic = "force-dynamic"`. Todo el dashboard se recalcula en cada visita sin ninguna capa de cache.
  - **Fix:** dado el volumen de datos y que las páginas son internas (no público masivo), esto es aceptable por ahora — pero si el N+1 de arriba se resuelve, evaluar `revalidate` corto (60-120s) en `/reporte` para amortiguar clicks repetidos de "Actualizar".
- **[web][contraste]** `text-white/40` sobre `--navy-brand` (#003865) en la única pantalla pública de la app — contraste real ≈3.19:1, falla WCAG 1.4.3 (mínimo 4.5:1 para texto de 12px). `src/app/(auth)/login/page.tsx:28` — texto "Solo cuentas @maestra.cl..." (información de autorización, legalmente relevante).
  - **Fix:** subir a `text-white/60` o superior (≈5.3:1) — mismo patrón que la línea 13 del mismo archivo, que sí pasa.

## 🟡 Media prioridad

- **[seguridad]** 3 Server Actions que escriben datos financieros/nómina con `service_role` (bypassa RLS) no verifican `session` explícitamente dentro de la función — dependen solo del middleware (`src/proxy.ts`). Inconsistente con el patrón correcto ya usado en `override.ts:24-25`. Archivos: `refresh.ts:548`, `upload-manual.ts:76`, `run.ts:275`.
  - **Fix:** agregar el mismo guard `if (!session?.user?.id) { ... }` al inicio de las 3 funciones — defensa en profundidad, no explotable hoy pero frágil si algún flujo futuro deja de pasar por el matcher del middleware.
- **[datos]** 12 columnas FK sin índice dedicado (una con `ON DELETE CASCADE`: `payroll_line_items.source_document_id`). `20260804000001_initial_schema.sql` (ver detalle en cobertura). Impacto performance, no seguridad.
- **[web]** Botón "✓" (checkmark unicode) sin `aria-label` en `sence-editable-cell.tsx:95-101` — accessible name no descriptivo para screen readers.
- **[web]** 2 inputs de datos financieros/dotación críticos sin `<label>`/`aria-label`: file upload en `upload-headcount-manual-form.tsx:61` y el input numérico de SENCE en `sence-editable-cell.tsx:84`.
